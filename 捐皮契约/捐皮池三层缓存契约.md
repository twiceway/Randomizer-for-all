## 目的

- **捐皮种类**以 `捐皮契约/` 黑白名单为唯一人工真源（不按 prep 张数反推种类数）。
- **分离**「游戏资源快照」与「契约策略」与「每槽可抽池」，避免现网 **扫图捐皮 + 白名单再补合成** 导致同 npc 双份皮（如 5 池 61 种 vs 113 张 `c0000`）。
- **白名单变动**只重 **合成运行缓存**，不重复全图捐皮扫描。

---

## 三层结构

```
① 捐皮全量库（donor_catalog）     ← MSB 扫一次，mod/图变才重扫
② 槽位全量库（enemy_index slots） ← MSB 扫一次，槽位变才重扫
        │
        │  捐皮契约：白名单 / 黑名单（你改表即变）
        ▼
③ 运行 prep（enemy_slot_prep）    ← 合成；generate 只读此层
        ▼
   spawn_map → apply-map
```

| 层 | 文件（现网 / 目标） | 内容 | 谁改 |
|----|---------------------|------|------|
| **① 捐皮全量库** | `cache/enemy_index.json` 内 `templates`（**R3+** 白名单择优见 `cache/bundle_catalog.json`） | 全图 MSB 捐皮模板：`template_id` · model · npc · think · **chara** · 行为 tags | **仅** CNV `mod/map` MSB 更新、新怪、捐皮槽大改 |
| **② 槽位全量库** | `cache/enemy_index.json` 内 `slots` | 全图待随机槽：`map_id` · entity · src_cat · slot_tags | 同上（槽位结构变） |
| **契约** | `捐皮契约/捐皮白名单_当前.*` · `捐皮黑名单_当前.*` | **种类**（池 + model + npc）；**无** chara 列 | 人工审计 / `_apply_donor_contract.py` |
| **③ 运行 prep** | `cache/enemy_slot_prep.json.gz` | 每槽 `o` 池（compat 后的捐皮 id 列表）+ **`w` 烘焙 npc/think**（R5 generate 直读） | **R3/R5**：只读 `bundle_catalog` + `slot_tags` + `bundle_slot_compat` 合成；指纹不一致硬拒绝 generate |

**废止**：prep 从全图 templates 再筛 + `supplement_contract_allowlist_templates` 注入 `chara=-1` 合成行与地图皮叠双份 — **T-060 已用 `compose_allowlist_donor_templates_by_cat` 去重**。

## ③ 怎么从 ① + 契约合成（核心规则）

### 输入

1. 读 **①** 全部捐皮模板（客观参数，含地图真人设的 `CharaInit`）。
2. 读 **白名单**：仅 `npc`（+ 池/model 校验）进入候选。
3. 读 **黑名单**：禁捐 / 禁随机 npc **剔除**（与现网 `_apply_donor_contract` 一致）。

### 去重（与白名单种类对齐）

- 白名单 **一行 = 一种**（一个 npc 在一个池里的一条契约）。
- 合成进 ③ 的捐皮：**每个白名单 npc 在对应池只保留 1 张皮**（禁止同 npc 多 template 同时进池抽签）。
- 多张地图皮命中同一 npc 时 **择优 1 张**：
  1. `model=c0000`：**必须** `chara > 0`（有真人设）；多条则任取一条（建议 `chara` 最大或固定取首条扫描序）。
  2. 非 `c0000`：优先地图模板；无地图命中见下条。
- **禁止**为已在 ① 中有真人设皮的 npc 再注入 `chara=-1` 的合成行。

### 白名单有、① 无

- **默认**：该 npc **不进 ③**（契约与游戏资源不一致 → 待补 MSB 或改白名单）。
- **可选实现**：允许最小 `synthetic:contract_{池}_{npc}`，但 **chara 须从 ① 同 model 其它 npc 或一次性索引推导，禁止 -1**（非白名单加列）。

### ① 有、白名单无

- **不进 ③**（即使全图扫到也不进捐皮池）。

### 与 apply 的关系

- `MsbEnemyPoc` 换皮用 spawn 行的 model/npc/think/**chara**，**不**再读捐皮来源 MSB。
- `template_id` 仅用于日志 / ensure model；③ 合成须保证写入 spawn 的 **chara 有效**（`c0000` 尤其）。

## 何时重建（不必每次 prep 都扫捐皮）

| 事件 | ① 捐皮全量 | ② 槽位全量 | ③ prep |
|------|------------|------------|--------|
| 改白名单 / 黑名单 | 否 | 否 | **是**（仅重合成） |
| 改概率矩阵 / 换种子 | 否 | 否 | 否 |
| 改 compat / Boss 封禁 / `PREP_VERSION` | 否 | 否 | **是** |
| CNV 更新 `mod/map` MSB | **是** | **是** | **是**（先 ①② 再合成 ③） |
| 改 hub/talk/被动动物等 skip（生成时重判） | 否 | 否 | 否（现网 `revalidate_prep_skip_key` 仍成立） |

**命令口径（目标）**：

- `index-export`（或等价）：只建 **① + ②**。
- `prep` / `compose-prep`：读 ① + 契约 + ② → 写 **③**；**不**再全图扫捐皮入池。
- 契约变更后：`_apply_donor_contract.py` → **只跑 prep 合成**（不必 index-export）。

## 验收（实现后）

1. `prep` 后：各池捐皮 **种类数 = 白名单 `by_category` 对应种数**（去重按 npc，非 template 张数）。
2. 5 池：`c0000` 捐皮 **0 条** `chara≤0`。
3. `smoke --map-filter m30_04`：蒙流 `c3400_9000` 不得 tgt=5 红灵（洞墓 Boss 锁池）。
4. 改白名单删 1 条 → 只重跑 prep 合成，**不**触发 index-export。
